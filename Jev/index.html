一分钟速览

如果你只看一屏：Jev 是决策模型而非语言模型。它的价值不在「更聪明」，而在于把 AI 应用里最高频、最贵、最不起眼的「判断」环节，压缩到毫秒级与万分之一美元级。

🧠 它是什么

TypeSafe AI 于 2026-09-15 发布的首个「系统一模型」。输入 state + questions，单次前向并行返回类型化答案（Choice / Score / Noul）与校准概率，不生成任何文本。

🎯 解决什么

Agent 循环里最贵的不是规划，而是每天几十万次的原子判断：该不该继续、调哪个工具、有没有风险。这些判断过去每次都要调用千亿参数 LLM，3–329 秒、幻觉不断。

⚙️ 核心原理

跳过自回归解码，概率分布直接「长」在答案字段上；训练方法 RLCD（面向校准决策的强化学习）优化「概率是否诚实」而非「回答是否讨喜」。

📊 关键数字

官方峰值：快 193.6×、省 444.6×、校准误差 ECE 0.0313。独立实测：快 5–25×（方向成立、量级缩水）；49 项任务中 42 项匹敌或超过 LLM 基线。

🚀 真实落地

Vercel 首日 13% 付费团队接入（平台史上最快）；Cloudflare、OpenRouter、LangChain 同步上架；48 小时内社区产出 40+ 项目：浏览器 Agent、编码护栏、邮件分诊、Doom 实时玩家……

⚠️ 必须警惕

「零幻觉」只保证输出在 schema 内，不保证选对；概率绝不能直接接资金/删库等不可逆操作——已有交易机器人亏损 $31,680 的真实翻车案例。

01

出发点：RLHF 的「亲生作者」为何反水

理解 Jev，要先理解它创始人的身份反讽：Diogo Almeida 在 OpenAI 工作约四年，是 InstructGPT 那一代 RLHF 训练流程的核心作者之一——「让模型听得懂人话、讨人喜欢」的那套方法，他是亲手参与者。而 Jev 的整个立意，建立在对这套方法的反思之上。

「（RLHF 调教出来的模型）谄媚、过度自信、幻觉……甚至连在 LM Arena 上吃香的那种风格——加粗、斜体、表情符号——都不是在简单地回答问题。」 "Sycophancy, overconfidence, hallucination… it doesn't answer the question simply."
—— Diogo Almeida，Latent Space 播客《Jev: System One models for Prod, not God》深度访谈 [01:52]

🗣️ 问题一：被 RLHF「惯坏」的模型不适合做决定

RLHF 把 LLM 优化成了「讨好人类偏好的聊天机器」，附带三个结构性副作用：幻觉、谄媚、永远离不开人。在 Latent Space 长达 2 小时 20 分钟的首次深度访谈里，Almeida 把 RLHF 的三条技术路线（Christiano 2017、Stiennon 2020，以及他亲手参与的 InstructGPT）统称为「错误的北极星」——它们优化的是讨人喜欢，而软件最需要的可靠性（reliability）无人优化。结果就是：每个生产系统都必须留一个人在环里兜底。

💸 问题二：开发者的账单，早就被「判断题」吃掉了

一个 Agent 循环里真正贵的调用往往不是规划，而是那些微不足道的判断：这一步该调哪个工具？这个页面值不值得读？这个动作有没有风险？任务做完了吗？它们每天发生几十万次，每一次都在向千亿参数模型要一段完整回答——官方引用的端到端延迟 3–329 秒，输出 token 比输入贵约 5 倍，还随时可能编出你没定义过的工具名。

图 1 · Jev 的出发点：Agent 循环里高频「原子判断」的成本与可靠性黑洞

第三个出发点更本质：机器之间的通信，本来就不需要自然语言。软件消费的是类型、枚举与概率，不是散文。让一个逐 token 写散文的机器去做接口调用，再用正则和 JSON 解析把散文「翻译」回结构，是这一代 AI 应用里最大的隐形成本。TypeSafe 的判断是：与其继续把模型调得更会说话，不如造一个从不说一句话的模型。

02

命名：两个思想来源，一份宣言

「Jev」这个名字藏着公司的全部世界观：一半来自心理学家卡尼曼，一半来自 19 世纪经济学家杰文斯（William Stanley Jevons）。

🧩 来源一：卡尼曼的双系统理论

《思考，快与慢》把思维分成两个系统：系统一快速、直觉、自动化，比如一眼看出别人的情绪；系统二缓慢、费力、深思熟虑，比如解一道数学题。TypeSafe 认为：今天的 LLM 做链式推理是「系统二」的工作，而软件里海量的分类、路由、守门，需要的是「系统一」——Jev 正是为此造的第一类模型，公司干脆把品类命名为 System One Model。

系统一 = 快 · 直觉 · 便宜系统二 = 慢 · 推理 · 昂贵

⚖️ 来源二：杰文斯悖论（Jevons Paradox）

1865 年，杰文斯在《煤炭问题》中提出：蒸汽机效率提高，反而让煤的总消耗量暴涨——因为便宜的动力解锁了无数过去不划算的用途。TypeSafe 把这条悖论印在首页，赌注是：当单次「机器判断」便宜一个数量级，判断的总用量会涨好几个数量级——过去只敢抽样审查的场景，将变成全量、实时、每次都判断。

效率↑ → 单价↓ → 总量↑↑模型名 Jev = Jevons

Diogo 在 Latent Space 访谈中的原话："Jev is meant to be optimized for intelligence per dollar, hence the name Jev."（Jev 要优化的是「单位美元智能」，名字正来自 Jevons。）

目的与定位：不是替代 LLM，而是给它配「反射神经」

官方定义：系统一模型是一类为快速、结构化、可被软件直接消费的决策而生的模型——它评估一个 state，返回类型化答案与概率。它刻意不做的事，和它能做的事同样重要。

一句话选型规则：如果这个判断的答案能从一个有限集合里枚举出来（哪个部门 / 紧不紧急 / 危不危险），用 Jev；如果答案本身需要被「想出来」（怎么设计 / 为什么错 / 写什么代码），用 LLM。LangChain 官方的定位表述是「complement，补充」而非「replacement，替代」：LLM 负责开放推理，Jev 负责沿途的高频结构化判断。

它在架构里的位置：Agent 缺失的那层「判断」

今天绝大多数 AI 应用里，「判断」和「生成」挤在同一段 prompt 的同一次调用里。Jev 主张把决策层从生成层中独立出来：判断成为一个可版本化、可度量、可单独替换的组件——就像当年把缓存、队列从业务代码里拆出去一样。LLM 只在真正需要思考与表达时被唤醒。

04

原理拆解：state 进，类型化决策出

Jev 的 API 只有两个核心概念：state（要评估的数据：文本或任意嵌套 JSON）和 questions（关于这份数据的一组类型化问题）。所有问题在一次前向传播里并行评估。

4.1 三种问题原语

CHOICE 多选一

从不超过 255 个预定义选项中选一项。返回：选中的选项 + 每个选项的概率分布 + 置信度。

典型用途：分类、路由、意图识别。

SCORE 量表打分

在有序等级上打分，可落在两档之间（如 1.6）。返回：连续分数 + 各档概率分布 + 置信度。

典型用途：风险分级、情绪打分、候选排序。

NOUL 是非判断

评估一个是/否命题，返回 0 到 1 的单一概率（命题为真的概率）。

典型用途：二次校验、条件分支、安全护栏。

词源：Noul = 伯努利分布（Bernoulli）—— CEO 在 Hacker News 上亲自确认（Simon Willison 考证）

4.2 快的根源：跳过自回归

LLM 逐 token 生成，每个 token 依赖前一个——哪怕只要一个 JSON 标签，也得先「写」出来再解析。Jev 的做法一句话可以说完：跳过自回归解码，让概率分布直接长在答案字段上。它用新架构 + 并行采样器，把 state 读一遍，所有问题的答案在同一个前向传播里同时产出。这就是为什么输出 token「便宜到不值得计量」，也是为什么多加一个问题几乎不增加延迟——只多花一点输入 token。

4.3 训练方法：RLCD —— 优化「概率是否诚实」

RLHF 优化的是「人类标注员更喜欢哪段回答」，RLVR 优化的是「可验证答案对不对」，而 Jev 的 RLCD（Reinforcement Learning for Calibrated Decisions，面向校准决策的强化学习）优化的是第三件事：给出的概率是否诚实——被它标成 80% 成立的事，事后要真的有约 80% 成立。官方在 1200 道 MMLU 上报告的期望校准误差（ECE）为 0.0313。据官方表述，模型基于 Transformer、完全使用合成数据训练；具体架构与权重未公开，外界猜测可能基于某个开放权重模型，Almeida 回应称真正的瓶颈是校准训练数据而非架构。

图 4 · 校准（calibration）概念示意 —— 注意：Jev 的校准数字目前全部来自官方自评，尚无第三方公开基准可复现

4.4 「零幻觉」的准确含义：保证接口，不保证真相

它保证的：输出永远在请求时锁死的 schema 之内。你给它「售后 / 物流 / 财务」三个部门，它永远编不出第四个部门；不存在 JSON 修复、重试循环、解析失败。官方评测里「0% 幻觉」统计的正是这类 schema 违规——恒为零。
它不保证的：选出来的选项是对的。它完全可能格式完好地选错。Hacker News 上一句被广泛引用的评论：「它无法吐出一个非法类型，但它仍然可以吐出一个错误的合法值。」类型化输出保证的是接口契约，不是真相。

4.5 它不是查表函数：一把带误差棒的测量工具

独立测试把 732 个相同判断重复跑三遍，只有 24% 的答案完全一致；好消息是漂移很小——中位漂移 0.010，p90 为 0.030。这直接决定阈值设计：某次实测中严重度打分 1.99，而人工介入阈值恰好是 2.00，差 0.01，规则就翻了个面。正确的用法是把它当测量仪器：看分布、设缓冲带、做重复采样，而不是当查找表。

上下文与容量限制：state + questions 上限 64k token（state + 最长单个问题 32k）；Choice 选项上限 255 个，超出需用「两段式」：先 Score/Noul 全量打分，再在 Top-K 上做 Choice。官方 jaggedness 页面列明的弱项还包括：数学与计数、日期比较、多跳推理、大噪声 state 干扰、对抗性注入。

实际案例：跑通的，和翻车的

7.3 翻车的那几个 —— 比成功更有信息量

  

    
⚠ 失败 · 交易机器人
一晚写出的交易 Bot
开发者让 Jev 持续读链上链下数据、选择买入或卖出。界面流畅，概率看着也「像回事」。
最终结果：亏损 $31,680 · 作者在 r/Artificials 发帖复盘

    
⚠ 失败 · 做市策略
Monad 生态 MON-USDC 做市
用 Jev 判断 Kuru 交易所上下一步涨跌，程序自动挂限价单低买高卖。错的不是模型，而是把交易简化成一道「涨还是跌」的判断题——在充满诱空诱多、假盘口、对抗性挂单的市场里，被主力假动作反复带偏几乎是必然。
杠杆放大下账户 大幅回撤 · 交易/做市代码见其 GitHub Gist

    
⚠ 失败 · 比特币信号
每分钟买/持/卖
表现很差；同期前沿大模型稍好——因为它会去交叉参考新闻。测试者的建议很直接：把 Jev 留在路由型决策上，离你的仓位远一点。
结论：概率 ≠ 策略

    
⚠ 揭示性测试 · 自动驾驶伦理题
它有自己的「默认规则」
小马智行架构师程墨设局：两车道、左有狗、右有女士、车速 200 迈。Jev 不到 1 秒答「急刹车」。把规则改为「优先到达、交规其次、安全最后」——仍选刹车（94%→77%）；改为「别管安全越快越好」——还是刹车（80%）。它先理解所有规则，再自己作选择，不是「指哪打哪」。
指令优先级被模型内置倾向覆盖

  


  
四个失败案例的共同教训：低延迟只能让决策执行得更快，它不会自动补上策略、风控与因果判断。付款、交易、删库这类不可逆动作，绝不能把模型概率直接接到执行接口上——至少要有仓位上限、止损、回测、模拟盘与人工批准。决策变便宜之后，该涨的不只是调用量，还有验证量。

边界与局限：官方 jaggedness 清单 + 三条使用前提

  
TypeSafe 文档里最有用的是「jaggedness（参差性）」页面——它直接告诉你不要拿它造什么。配合社区实测，边界相当清晰。


  

    

      
失败模式会发生什么正确做法

      
字面理解回答的是你写下的问题，不是你想问的问题把边界案例写进 criteria

      
数学与计数识别答案的「形状」而非真正数数在代码里计数；逐项用 Noul

      
日期比较把日期当文本读，而非有序值拆成 Choice 提取，代码里比较

      
多跳推理跳数越多，准确率掉得越快减少跳数；点名相关 state 字段

      
大噪声 state无关细节成为干扰项先过滤，只发问题需要的内容

      
对抗性内容注入指令可以挪动答案criteria 写具体；测试边缘案例

      
文本生成从未训练过生成交给生成式模型

      
中文场景准确率偏弱（实测约 64–65%），复合实体识别欠佳关键中文流程先自建小基准验证

    

  


  

    
前提 ① 答案空间可事先定义
正确答案必须在你给的选项里。若不在，它照样会从剩余选项里「格式完好地」挑一个错的。

    
前提 ② 问题可拆成原子判断
复杂逻辑要摊平成一组互相独立的原子问题并行问；拆不动的问题，说明该用 LLM。

    
前提 ③ 错误可验证、可回滚
三条缺任何一条，「便宜和快」只会让错误跑得更勤。接入前先用几十条带标注的真实数据验证概率。

  


  
其他现实约束：校准数字目前无第三方公开基准可复现（「你的场景就是你的基准」）；服务暂未向中国大陆开放；模型非确定性存在小幅度漂移——阈值要留缓冲带。怀疑者的观点也值得记录：r/singularity 热评称这是「行业重新发现分类模型」；r/LocalLLaMA 指出 gliformer 等零样本分类编码器早已能做类似的事。开源复现 openjev 用 Qwen3.5-4B 直读 logits，在 102 个对齐案例上拿到 0.845 模态一致率（Jev 官方 0.883）——接近，但不相等；差距大概率就在 Almeida 所说的「校准训练数据」上。

启示：比模型本身更重要的三条主张

  
Jev 是不是「新范式」见仁见智，但它背后三条架构主张，值得现在就画进你的系统设计图——哪怕暂时用小模型去填这个坑位。


  
主张一：决策层可以从生成层独立出来

  
判断成为一个独立的、可版本化、可度量、可单独替换的组件。架构上多出一条边界，就像当年把缓存和队列从业务代码里拆出去。难点也从「写提示词」变成了「设计决策图」——枚举、阈值、分支、人工闸门，需要有人认真设计。


  
主张二：校准概率是自动化的开关，不是附加指标

  
一个任务能 95% 做对、但说不清自己什么时候在那 5% 里的模型，等于不能自动化——因为人还是得全量复核。有了可用的概率，流程变成三段式闸门：


  

    
    
图 5 · 置信度三段闸门：校准概率让「敢不敢自动化」第一次有了工程答案

  


  
主张三：判断变便宜之后，判断的总量会暴涨

  
过去因为太贵，系统只敢抽查样本；当每次判断只要万分之一美元，全量扫描成为默认选项——每封邮件、每个工单、每次工具调用、每段引用、每页抓取的文档，都值得判断一次。需求侧的形态会被改写：路由、审核、重排、护栏这些「过去用关键词规则凑合」的环节，全部有了重做的理由。这正是「Jev」这个名字的赌注。


  
以及一条红线：概率永远不等于执行权。任何不可逆操作（资金、删除、外发），模型概率与执行接口之间必须有决策闸门——幂等、重试预算、回滚路径、人工批准。两个亏损案例（-$31,680 / 做市回撤）的教训就这一条。


  
LLM 负责「想」，Jev 们负责「反射」。
当判断便宜到可以全量、实时、每次都做，
软件架构里才真正长出了「神经系统」。
