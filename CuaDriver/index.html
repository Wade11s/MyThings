工具说成功，不算数 Cua Driver 怎么证明一次点击真的发生了

Cua Driver 是计算机使用代理的界面层：读一个窗口的无障碍树和截图，再点击、输入、滚动。 它跑在你已经有的那台机器上，不是虚拟机。自动化测试因此不能看退出码。 一格通过，只因为应用或桌面自己拥有的状态变了；测后台时，用户的焦点还得留在原地。 精确的拒绝也算通过。一声不响的成功不算。

00

先把两件测试分开

名字都叫「自动化测试」，问的却不是同一个问题。混在一起，就会用驱动的自测绿灯，去给自己的应用放行。

仓库 驱动有没有按契约做事

Rust 目录在真实桌面会话里驱动源码构建的夹具。格子通过与否，看夹具日记、无障碍读回、焦点哨兵和录像，不看工具自己说了什么。Python 不复制这套矩阵。

你的应用 这次操作有没有达成后置条件

观察，用新鲜的 element_token 行动，再用 verify_state 或你自己的外部标记收口。effect:"confirmed" 只说明无障碍读回了，任务可以仍然没完成。

你看见的信号能不能当通过它实际证明了什么
工具返回 ok，进程退出码 0不能调用被接受了。Electron、Catalyst、网页内容可以回显一个没生效的写入。
effect:"confirmed" / verified:true还不够只有无障碍读回能让驱动自己确认。任务后置条件仍要另查。
effect:"unverifiable"既不是过也不是挂送达不能证明生效。去看夹具日记或新快照，不要立刻重试。
verify_state = satisfied能，在谓词范围内1–8 个谓词的与，并且连续 stable_samples 次都满足。默认 2 次。
verify_state = unknown不能匹配含糊、观察不到、网页状态不可信，或稳定样本不够。未知不是成功。
截图「看起来对」不能单独算驱动可以带回最终截图，但不解释这张图。解释是调用者的事。
replay_trajectory 跑完不能它按原参数重放。pid、窗口号、token 都可能已经过期。

02

驱动自己的三层验证

根目录 Development.md 把 cua-driver 的验证写成三层。上层不能代替下层，下层也不能冒充上层。

1 单元与协议

schema、传输、会话、元素身份、工具边界 fuzz。不启动仓库夹具，通常也不要桌面。它们证明驱动做了一个确定的决定，不证明点击进了应用。

2 源码夹具 E2E

Electron、Tauri，加上 AppKit、SwiftUI、WPF、WinUI 3、GTK3 等。多数用例标了 #[ignore]，由各 OS 的规范 runner 在交互式桌面里挑选。这是桌面行为的源头。

3 已安装应用

macOS 的 Calculator / TextEdit 在规范登录车道里，是补充，不取代夹具。LibreOffice Writer 只覆盖 Windows 的 MSAA 回退，缺了就失败，但不是 run-all 的一部分。

普通 CI 绿灯 ≠ 桌面绿灯。 单元门禁止跑被 ignore 的 GUI 测试，也不许把「夹具没装」变成静默跳过。桌面格需要已登录的交互会话：Windows 不能在 Session 0；macOS 需要辅助功能和屏幕录制；Linux 的 X11 与 Wayland 是两列，不能互相继承。
03

一格测试实际在跑什么

四个所有者各管一段。测试文件不负责装系统，夹具应用不负责断言驱动对不对，runner 不负责改预期。

工具 ok 只出现在中间。左右两侧的 oracle 才决定格子。

谁拥有不拥有
Rust 集成测试场景、驱动调用、断言、动作元数据装系统、编译夹具
cua-driver-testkit会话、拉起夹具、截图、录像、轨迹场景清单
夹具应用看得见的控件，以及外部可观察的状态标记「驱动对不对」的断言
OS runner构建环境、用户会话、用例选择、收集产物改测试行为的定义
哨兵自己要先被证明能失败。 行为格开始前，预检会故意向盖住目标的 Electron 哨兵注入输入，并故意把后台目标抬起来。只有泄漏和短暂失焦都被观察到、哨兵再恢复全遮挡，这一车道的结果才可信。一个坏掉的守卫会让每一格后台测试看起来都是绿的。

规范入口不靠你自己拼 cargo test 过滤器。Windows 是 scripts/ci/windows/run-rust-e2e.ps1 -RequireGui；Linux 是 scripts/ci/linux/run-rust-e2e.sh；macOS 验收在已登录的 Lume 车道 libs/cua-driver/tests/runners/macos-lume/run-all.sh。未过滤的共享跑还要求最少格子数：Windows / Linux 80，macOS 120。对上 0 个格子仍然失败。

04

矩阵是维度，不是一张成绩单

切片器只根据仓库文档推导这一格必须证明什么。它不知道你手头的 0.31.0 二进制上次 CI 绿没绿。选一个「这个 OS 根本没有的夹具」，会看到继承覆盖率有多容易。

维度取值不要理解成
寻址 AX无障碍 / UI Automation / AT-SPI 元素动作不是截图模式。树和截图是同一次观察。
寻址 PX同一张截图上的坐标不保证走物理指针。后台像素仍可能被命中测试后改走语义动作。
后台不抬窗口、不抢前台、不挪真光标不是「用户完全无感的所有手势」。做不到就结构化拒绝。
前台允许把目标带到前面不是所有平台都会恢复你原来的前台应用。
窗口 / 桌面一次调用自己选目标会话不是捕获范围，也不是权限。
05

夹具卖的是外部标记，不是另一个点击器

共享页面 tests/fixtures/shared/web/index.html 被 Electron 和 Tauri 加载；macOS 的 WKWebView 宿主再跑同一份目录。控件旁边有测试能读到的标记，而不是把「再点一次」当成断言。

为什么必须源码构建

已安装的 Chrome 版本、用户配置、窗口位置每台机器都不一样。夹具从仓库编译，标识写在 shared/scenarios.json。二进制不进 git。缺夹具在规范跑里是失败，不是跳过。

oracle 长什么样

共享格看动作专用的外部标记。Windows 前台文本还会读夹具原子替换的状态文件，对照 CJK、数字、emoji 和换行，只规范化换行符。焦点断言证明「没抢焦点」，证明不了「应用变了」——两样都要。

共享目录写明：每个夹具应用 40 个带证据的格子，覆盖点击、文本、键盘、先输入再回车、滚动、子窗口的 AX/PX × 前台/后台，以及 PX 拖拽和 AX 编辑器保存的两种投递。后台拒绝只有在声明过的错误码加上无焦点、无叠放变化、无输入泄漏时才算有效观察。要求送达的格子，拒绝就是失败。

06

证据绑在那一次提交上

规范 GUI 格要留下可解析的事前/事后状态、非空的目标窗口图、轨迹和 MP4。单元测试要日志，不要桌面录像。

录像

夹具就绪、前后台姿态摆好之后才开始。派发前有 300 ms 基线，一直录到外部 oracle 收完。trajectory.json 必须以 behavior_video.status = "finalized" 结束。runner 用 ffprobe 检查 MP4。

每一步

动作前后的无障碍状态和目标窗口图。窗口捕获即使被别的窗口挡住，仍然只框那一个目标。共享行为矩阵的守护进程故意加 --no-overlay，免得代理光标像素污染 oracle。

报告

cases.jsonl 声明预期，results.jsonl 记录观察到的行为。GitHub 摘要一行一格，链到该车道归档里的精确录像路径。缺了预期证据，报告失败。有一处窄例外：Windows 成功的 bring_to_front 恢复，最小化目标可以没有事前图。

07

「支持」的意思是有夹具证据

公开平台页把支持分成三档：规范 Rust 夹具证明了应用或桌面状态，才叫 Supported。常见路径证明了、其余形状会结构化拒绝，叫 Supported with limits。后端在、代表覆盖不全，叫 Experimental。未列出的动作不要假设能用。

平台公开账本里的状态测试时最容易误判的边界
WindowsSupported。规范覆盖 Electron、Tauri、WPF、WinUI 3、WebView2守护进程必须在交互会话，不能在 Session 0。部分后台 Chromium 手势和提升完整性边界仍不可用或未证明。
macOSSupported。规范覆盖 Electron、Tauri、AppKit、SwiftUI、WKWebView需要辅助功能与屏幕录制，权限属于 CuaDriver.app，不是启动它的终端。不在当前 Space 的 SwiftUI 窗口会按系统设计丢掉树。部分后台滚动和拖拽是结构化拒绝。AppKit 后台拖拽被写成精确拒绝。
Linux X11Supported with toolkit limitsX11 收下事件，不等于应用处理了。拒绝合成后台事件的工具包应得到明确拒绝，而不是静默成功。
Linux Wayland按合成器记账，不是一个统一 API语义 AT-SPI 动作可以在不抬窗口的情况下成立。任意原始后台像素注入对普通客户端不可用：知道坐标改变不了合成器把事件送给谁。Sway 有完整目录；GNOME / KDE / Hyprland 不能继承它。
Hyprland 的原始后台输入是带资格的例外，不是「Wayland 已支持」。 平台页记录的资格是 LibreOffice Calc 26.2.5-3 和 Inkscape 1.4.4-6，证据日期 2026-09-07。插件默认关闭。普通 GTK、Electron、Tauri 夹具不能用来证明这条插件投递。前台路由会改焦点和光标，并且不承诺恢复。派发确认仍然不是应用效果。

浏览器变异必须从精确的 (pid, window_id) 绑定开始。独立 Chrome / Edge 在 Windows、macOS、Linux X11 上有已证明的页面路由，但信任级别不同：macOS 和 Linux X11 上，受信任的 CDP 指针输入会在派发前返回 browser_input_trust_unavailable。Safari 和 Firefox 只有原生发现和 AX/PX 回退，没有已广告的类型化浏览器变异引擎。Tauri、WKWebView、WebKitGTK 和常见的分裂进程 WebView2，文档写的是身份加上无副作用的结构化拒绝。

08

用它测你自己的窗口

抄判据，不要抄目录。你的应用如果没有外部标记，verify_state 只能检查无障碍投影表达得了的那一部分。

# 同一条 MCP 连接或一次 SDK 会话里做完这三步。
# 不要拆成三次 cua-driver call —— 每次 call 都是一个一次性会话。
get_window_state { "pid": 844, "window_id": 10725, "include_screenshot": false }

click {
  "target": { "kind": "window", "pid": 844, "window_id": 10725 },
  "element_token": "<这次快照 elements[] 里的 token>",
  "delivery_mode": "background"
}

verify_state {
  "pid": 844,
  "window_id": 10725,
  "stable_samples": 2,
  "expect": [
    { "element": { "selector": { "label_contains": "Count" }, "value_equals": "1" } }
  ]
}

行动之后看哪个字段

字段下一步
confirmed有可读回的发布。仍要核对任务后置条件。
partial只有报告的那一部分落地了。先看，再修。
unverifiable不能用「再点一次」当验证。先重新观察。延迟的提供者可能在调用返回后才发布，立刻重试会把字打重。
suspected_noop现有证据像是没发生有用的变化。
refused + stale_element_token快照已被更新的读取作废。重新观察。不是「元素路由坏了」。
escalation建议下一档：像素、页面或前台。它不是授权，也不会自动重试。

0.31.0 的 click 写明了阶梯：后台 AX（element_token）→ 快照 → 后台像素 → 快照 → delivery_mode:"foreground"。token 优于坐标，因为它能点到后台、最小化、隐藏、甚至不在当前 Space 的窗口，并且标明角色和标签。像素留给画布、视频、WebGL 这些树上没有的东西。带修饰键的点击要求前台，因为 macOS 要看到真实的修饰键状态。

最好的应用测试，是夹具那一套的缩小版。 给窗口一个测试能读到、用户路径也会写到的标记：计数器文件、状态接口、无障碍值。只靠「按钮还在」证明不了点击被接受了。驱动测浏览器夹具时，甚至用单独的 /state 端点确认输入值，而不是相信输入框的回显。

10

录制是证据，回放不是回归脚本

轨迹适合回答「刚才发生了什么」。它不适合当成明天还能跑的测试。回放是一次新的动作序列，不是语义规划器。

一次录制留下什么

必须在同一条持久 MCP 连接上 start_recording → 行动并验证 → stop_recording。视频默认关，要显式 record_video:true。每个 turn-NNNNN/ 有前后状态、前后图、action.json 和 evidence.json。看 video_active 和 last_error，不要只看工具成功。文件路径不等于片子能播。

为什么不能当脚本

replay_trajectory 按词典序重放原参数，只接受目录、delay_ms、stop_on_error。只读快照不在动作序列里，所以它不会刷新元素句柄。记录下来的 pid、窗口号、token、浏览器 ref 和几何都可能过期。像素和按键同样依赖当初的目标身份、布局和焦点。

取消、部分成功、未知结果，不许重放来「看看当时到底点没点上」。 传输中断时，输入可能已经送出，响应却丢了。回放期间如果录制还开着，回放自己会被记成新的 turn。源目录和输出目录必须分开。一个运行时只有一个录像机，stop_recording 会停掉当前那个，不管是谁开始的。
11

写测试前先接受的边界

一台桌面，一个控制者

不同会话不隔离焦点、键盘、应用状态和快照缓存。原生输入一次只放行一个动作。并行 GUI 测试会互相踩。macOS 上如果别的 MCP 客户端连着同一个守护进程，它还能改掉你正在断言的录制状态。专注跑要用专用 socket。

后台做不到，就拒绝

background_unavailable 是契约的一部分，不是「没藏好」。Wayland 上，坐标告诉驱动窗口在哪，改变不了合成器的座位把原始事件送给谁。测试应断言拒绝码和「没有副作用」，而不是重试到前台。

权限在运行时身份上

macOS 的辅助功能和屏幕录制属于 CuaDriver.app（com.trycua.driver），不是终端。Windows 上 SSH 进 Session 0 的进程看不见桌面。权限状态不是「现在真的录得到」的证明。

版本不要焊死成证书

本页的目录规模和 runner 来自 2026-10-03 的 main。本机二进制是 0.31.0，用来核对 click / verify_state 的字段。技能包版本标识它的来源发布，不是正在跑的守护进程，更不是「整份 E2E 已通过」。

还有一些表面根本不在规范矩阵里：GTK4、Qt、VTE、GL 画布不能用 Electron/Tauri 的共享覆盖来冒充。感知扩展的捕获循环是单独车道：点击必须带同一次 capture_id，用过的捕获返回 capture_not_found，超过寿命返回 capture_expired，而且这两种拒绝都不能改变夹具。那是另一条测试契约，不是默认驱动的一部分。
